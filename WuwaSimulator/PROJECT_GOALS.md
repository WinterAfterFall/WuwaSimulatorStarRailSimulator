# WuwaSimulator — จุดประสงค์ & แนวทางการพัฒนา

## จุดประสงค์

1. **ขั้นแรก** — ทำโปรแกรมจำลองระบบต่อสู้ของ Wuthering Waves ที่:
   - **คำนวณได้จริง** — DPS / damage / rotation ตรงกับสูตรของเกมจริง
   - **อ้างอิงได้** — ทุกสูตร ทุกค่าตัวเลข ต้องสามารถ trace กลับไปยังที่มา (ทดสอบเทียบกับค่าจริงในเกม หรือแหล่งอ้างอิงที่เชื่อถือได้) ไม่ใช่เดาหรือกะประมาณ
2. **ต่อยอด** — เมื่อ core simulation ทำงานถูกต้องและเสถียรแล้ว ค่อยขยายเป็น **Website** ให้คนอื่นใช้งานได้ (ไม่ใช่แค่รันผ่าน CLI/script เหมือนตอนนี้)

> หมายเหตุ: อย่ารีบข้ามไปทำ UI/Website ก่อนที่ core calculation (damage formula, rotation, stat system) จะแม่นยำและมี test คลุมเพียงพอ — ลำดับความสำคัญคือ **ถูกต้องก่อน สวยงามทีหลัง**

## แนวทาง Best Practice ที่ต้องการให้ยึดถือเสมอ

เป้าหมายระยะยาวไม่ใช่แค่ "ทำโปรแกรมนี้ให้เสร็จ" แต่คือการฝึกฝนแนวทางของโปรแกรมเมอร์ที่ดี ดังนั้นทุกครั้งที่เขียน/รีวิวโค้ดในโปรเจกต์นี้ ควรคำนึงถึง:

- โครงสร้างโค้ดที่ชัดเจน แยกหน้าที่ (separation of concerns) — เช่นที่ทำอยู่แล้วกับ `Services/`, `Simulator/`, `Models/`
- Type safety เต็มที่ (`strict: true` ของ TypeScript) — ใช้ type system ช่วยจับ error ตั้งแต่ compile time แทนที่จะปล่อยไป runtime
- Test coverage สำหรับ logic สำคัญ (damage formula, energy system, event scheduling) ก่อนต่อยอดฟีเจอร์ใหม่
- หลีกเลี่ยง over-engineering — ไม่เพิ่ม abstraction ที่ยังไม่จำเป็นต้องใช้จริง (ดู `CLAUDE.md` ส่วน "ข้อควรระวัง" ที่มี dead export หลายจุดอยู่แล้ว เป็นตัวอย่างที่ควรเลี่ยงไม่ให้เกิดซ้ำ)
- โค้ดที่อ่านแล้วเข้าใจ "ทำไม" ไม่ใช่แค่ "ทำอะไร" — comment เฉพาะจุดที่ non-obvious จริงๆ

## วิธีการสื่อสารที่ต้องการ

เมื่ออธิบายโค้ดที่เข้าใจยาก (โดยเฉพาะ TypeScript pattern ที่ค่อนข้างเฉพาะทาง เช่น generic, mapped type, conditional type) **ให้ลองเทียบเป็น C++ เวอร์ชันที่ใกล้เคียงที่สุดเท่าที่จะเป็นไปได้ประกอบด้วยเสมอ** — ถ้าไม่มี syntax ตรงตัวใน C++ ให้บอกตรงๆ ว่าไม่มี แล้วอธิบายว่าต้องเขียนแบบไหนถึงจะได้ผลลัพธ์เทียบเท่า (เช่น ต้องใช้ template metaprogramming, type erasure ฯลฯ)

เหตุผล: ผู้ใช้คุ้นเคยกับ C++ มากกว่า TypeScript pattern เฉพาะทางบางตัว การเทียบเคียงข้ามภาษาช่วยให้เข้าใจ "concept จริงๆ" ได้เร็วกว่าการอธิบายด้วย TypeScript syntax อย่างเดียว
