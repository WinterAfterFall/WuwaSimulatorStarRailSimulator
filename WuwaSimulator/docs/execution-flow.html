5
ประกาศ mergeQueues helper
manualBuilder.ts (local function)
function ช่วยรวมหลาย Queue<RotationAction> เป็น queue เดียว โดย dequeue จากแต่ละ queue เข้าคิวใหม่เรียงกัน (ยังไม่ถูกเรียกที่บรรทัดนี้ — แค่ประกาศไว้)
function mergeQueues(...queues: Queue<RotationAction>[]): Queue<RotationAction> {
    const merged = new Queue<RotationAction>();
    for (const q of queues) {
        while (!q.isEmpty()) merged.enqueue(q.dequeue()!);
    }
    return merged;
}

เรียก factory → สร้าง setupQueue / loopQueue
manualBuilder.ts
นี่คือจุดที่ factory function ที่เก็บไว้ใน unit.rotations (step 1, 3) ถูกเรียกจริง — แต่ละ factory รับ timeline แล้วสร้าง RotationBuilder ใหม่ คืน Queue<RotationAction> ที่มี closure รออยู่ (ยังไม่ execute ตัว action เอง) จากนั้น mergeQueues รวม queue ของ Test1+Test2 เข้าด้วยกัน 
const setupQueue = mergeQueues(
    test1.rotations.get("Burst")!(timeline),   // → Queue[Test1-Ult, Test1-BA1]
    test2.rotations.get("Burst")!(timeline)    // → Queue[Test2-Ult, Test2-BA1]
);
// setupQueue = [Test1-Ult, Test1-BA1, Test2-Ult, Test2-BA1]

const loopQueue = mergeQueues(
    test1.rotations.get("Standard")!(timeline), // → Queue[Test1-BA1, Test1-BA2, Test1-Skill]
    test2.rotations.get("Standard")!(timeline)  // → Queue[Test2-BA1, Test2-Skill, Test2-BA2]
);
// loopQueue = [Test1-BA1, Test1-BA2, Test1-Skill, Test2-BA1, Test2-Skill, Test2-BA2]
💡 setupQueue มี 4 action (รันครั้งเดียว), loopQueue มี 6 action (จะวนซ้ำตาม maxLoops)

director.run() — เริ่ม simulation จริง
Simulator/RotationDirector.ts
run() คือ entry point ของการจำลองทั้งหมด วนเรียก step() จนกว่าจะคืน false (ทั้ง setupQueue และ loopQueue หมด/ครบ maxLoops แล้ว) แล้ว drain event ที่เหลือด้วย timeline.runAll() 
public run(): void {
    while (this.step()) {}
    this.timeline.runAll();
}
9
step() — ทำ 1 action ให้จบสมบูรณ์
Simulator/RotationDirector.ts
ทุกครั้งที่เรียก step(): เช็ค lock ก่อน → ถ้าไม่ล็อค ดึง action ถัดไปมา execute → แล้ว tick timeline ต่อจนกว่า lock จะปลด (หรือ IPQ ว่าง) — การออกแบบนี้รับประกันว่า ทีละ action เท่านั้น ที่ทำงานในแต่ละรอบ ไม่มีทางที่ 2 unit จะชน queue กันเอง 
private step(): boolean {
    if (this.timeline.isGlobalLocked) return false;

    const action = this.nextAction();      // → step 10
    if (!action) return false;

    action.execute();                       // → step 11 (schedule ลง timeline)

    do {
        this.timeline.tick();               // → step 12
    } while (this.timeline.isGlobalLocked && !this.timeline.isEmpty);

    return true;
}
10
nextAction() — เลือก action ถัดไปจาก queue ไหน
Simulator/RotationDirector.ts
Priority: setupQueue ก่อนเสมอ (dequeue จนหมด 4 ตัว) แล้วค่อยสลับไปใช้ loopQueue — rotate() (dequeue+enqueue กลับ) ทำให้วนซ้ำได้ไม่รู้จบ, loopStepCount นับว่าวนครบ 1 รอบ (เท่ากับ loopQueue.length) หรือยัง เพื่อ increment currentLoopCount — เมื่อครบ maxLoops จะคืน undefined ทำให้ run() จบ 
private nextAction(): RotationAction | undefined {
    if (!this.setupQueue.isEmpty()) {
        return this.setupQueue.dequeue();     // 4 ครั้งแรก
    }

    if (this.loopQueue.isEmpty()) return undefined;
    if (this.currentLoopCount >= this.maxLoops) return undefined;  // จบเมื่อครบ 2 รอบ

    const action = this.loopQueue.rotate();

    this.loopStepCount++;
    if (this.loopStepCount === this.loopQueue.length) {  // ครบ 6 ตัว = 1 รอบ
        this.loopStepCount = 0;
        this.currentLoopCount++;
    }

    return action;
}
11
action.execute() — closure ยิง event ลง timeline จริง
Models/Characters/Test1.ts / Test2.ts
ทุก RotationAction เก็บ closure ที่สร้างไว้ตอน step 1/3 — พอถูกเรียก execute() ตอนนี้ closure จะ อ่าน timeline.currentFrame ปัจจุบัน (ไม่ใช่ frame ที่สร้างตอน setup) แล้ว schedule AttackActionEvent + NotificationEvent(EndAction) ลง IPQ ทันที 
// ตัวอย่าง: closure ของ "Test1-Ult"
() => {
    const t = timeline.currentFrame;             // อ่านค่าปัจจุบัน ณ วินาทีที่ execute จริง
    timeline.schedule(new AttackActionEvent(
        `Test1-Ult-f${t}`, t, ULT_DURATION, unit, ActionType.Ult, true, 0,
        () => console.log(`[f${t}] Test1-Ult`)          // onExecute callback
    ));
    timeline.schedule(new NotificationEvent(
        `Test1-Ult-end-f${t}`, t + ULT_DURATION, NotificationType.EndAction, unit
    ));
}
⚠ schedule แค่ 2 event ต่อ 1 action เท่านั้น (attack + end) — ต่างจาก void-fn approach ที่เคยพิจารณาไว้ ซึ่งจะ schedule event ของทั้ง rotation รวดเดียว (ดู void-fn-problem.html ในโฟลเดอร์ Test/manual)
12
tick() — pop event, execute, จัดการ lock
Simulator/CombatTimeline.ts
pop event ที่ frame น้อยสุดจาก IPQ → เลื่อน currentFrame ไปตาม event นั้น → execute event → เช็คชนิด event เพื่อจัดการ isGlobalLocked: ActionEvent ที่ isManual=true จะล็อคทันที, NotificationEvent(EndAction) จะปลดล็อคพร้อม unit.setFree() 
public tick(): CombatEvent | undefined {
    const event = this.ipq.pop();
    if (!event) return undefined;

    this.currentFrame = event.time;
    event.execute();   // AttackActionEvent → unit.setBusy() + onExecute?.()

    if (event instanceof ActionEvent && event.isManual) {
        this.isGlobalLocked = true;                       // 🔒 ล็อค
    }
    if (event instanceof NotificationEvent) {
        if (event.notifyType === NotificationType.EndAction) {
            this.isGlobalLocked = false;                  // 🔓 ปลดล็อค
            event.unit?.setFree();
        }
    }
    return event;
}
💡 ย้อนกลับไป step 9 — do-while จะวน tick() ซ้ำจนกว่า isGlobalLocked จะกลับเป็น false (ปกติคือ 2 tick ต่อ 1 action: Attack แล้ว Notification) แล้วจึงกลับไปหา action ถัดไป
