Constants/

app/Constants/Enum.ts
Enum.ts Core
รวม string enum ทั้งหมดที่ใช้ทั่วโปรเจกต์ ทุกตัวเป็น string enum (value เป็น string ไม่ใช่ตัวเลข) เพื่อให้ debug/log อ่านง่าย และใช้เป็น key component ของระบบ stat แบบ Map-based
UnitStatusenum
Alive / Death — สถานะการมีชีวิตของ unit
Sideenum
None / Ally / Enemy — ฝ่ายของ unit
StatsTypeenum
ประเภทค่าสถานะทั้งหมด (AtkP, FlatAtk, Hp, DefP, CR, CD, Dmg, Amp, Sp, DefShred, DefRed, ResRed, ResPen, DmgRed, ElemRed ฯลฯ) — ใช้เป็น dimension แรกของ stat key
ActionTypeenum
None, BA, HA, Skill, Ult, Echo, Intro, Outro, TB — ประเภท action ที่ตัวละครทำได้
ElementTypeenum
None, Glacio, Fusion, Electro, Aero, Spectro, Havoc — ธาตุของสกิล/ตัวละคร
WeaponTypeenum
None, Broadblade, Sword, Pistols, Gauntlets, Rectifier — ประเภทอาวุธ
ActionStateenum
Free / Busy — สถานะว่างของ unit สำหรับ lock system
NotificationTypeenum
ChangeToAuto, EndAction, BuffExpired, DebuffExpired — ประเภท signal event ใน timeline
TriggerEventenum
EnergyIncrease — event ที่ TriggerBus emit ได้ (เพิ่มใหม่ต้องคู่กับ TriggerEventMap ใน TriggerBus.ts)
EnemyPositionenum
Vanguard="0", Midrange="1", Rearguard="2", OutOfRange="3" — ตำแหน่งยืนของศัตรู ใช้กรอง target ตาม SkillRange
MultiplierTypeenum
Atk="atk", Hp="hp", Def="def", Const="const" — key ของ scaling multiplier ใน Damage
SkillRangeenum
None, Contact, Midrange, Ranged, Global — ระยะของสกิล ใช้เทียบกับ EnemyPosition เพื่อกรอง target

Models/

app/Models/Unit.ts
Unit.ts Core
Base class ของทุก unit (ทั้ง Ally และ Enemy) เก็บระบบ stat แบบ Map<string, number> โดยสร้าง key จากการรวม enum value เข้าด้วยกัน (1–3 dimension: Stat / Stat-Action / Stat-Element-Action)
class Unitclass
generateKey()private — ประกอบ key string จาก 1-3 args ตามจำนวน dimension ที่ส่งมา
isAlive() / setDead()lifecycle helper ตรวจ/ตั้งสถานะตาย
getStats()3 overloads — อ่านค่า stat ตาม dimension ที่ระบุ, default 0 ถ้าไม่มี
setStat()3 overloads — ตั้งค่า stat ทับของเดิม
addStat()3 overloads — บวกเพิ่มจากค่าเดิม (เรียก getStats+setStat ภายใน)
hasStat()3 overloads — เช็คว่ามี key นี้ถูกตั้งไว้หรือยัง
app/Models/AllyUnit.ts
AllyUnit.ts Core
extends Unit — เพิ่ม combat state เฉพาะฝั่งผู้เล่น: energy, HP/shield, rotation definitions, และ tracking maps (buff/stack/dmgRecord) พร้อม type TimelineRef แบบ structural เพื่อเลี่ยง circular import กับ CombatTimeline
type TimelineReftype
structural type { schedule(event), currentFrame, triggerBus } — CombatTimeline satisfy type นี้โดยอัตโนมัติ ไม่ต้อง import ตรง
class AllyUnit extends Unitclass
state: isOnField, actionState, level/baseAtk/baseHp/baseDef, elementType/weaponType/resonanceChain, rotations (Map ชื่อ → factory), energy/maxEnergy, concentoEnergy, currentHP/currentShield, stacks/buffNote/gauges/buffCheck, dmgRecord/maxDmgRecord
isFree()true ถ้า actionState === Free
setBusy() / setFree()เปลี่ยน actionState — เรียกจาก event execute() และ CombatTimeline.tick()

Services/

app/Services/Combat/EnergyService.ts
EnergyService.ts Core
จุดเดียวที่ mutate unit.energy ได้ — บังคับให้ energy gain ทุกทาง (rotation, DamageCalculate) ต้องผ่านฟังก์ชันนี้ เพื่อให้ TriggerBus เห็น event ก่อน clamp กับ maxEnergy
increaseEnergy(unit, amount, triggerBus, actionType?)function
1) triggerBus.emit(EnergyIncrease, {unit, amount, actionType}) — listener เห็นค่าดิบก่อนโดนตัด (ตรวจ overflow ได้)
2) unit.energy = Math.min(maxEnergy, energy + amount) — clamp จริง
app/Services/Damage/DamageCalculate.ts
DamageCalculate.ts Core
สูตรคำนวณ damage หลักของเกม (WuWa formula) — รวม stat จากหลาย dimension (base/action/element) แล้วคูณ ผ่าน pipeline: dmgBonus × crit × amp × sp × def × res × elemRed × reduction
sumStat(unit, statType, damage)function (internal)
รวมค่า stat จาก base + ทุก action ใน attackTypeList + (ถ้าเป็น element-dimension stat) ธาตุของ skill แล้วหาร 100 อัตโนมัติถ้าไม่ใช่ flat stat
computeAttackerStats(attacker, damage)function (internal)
รวม atk/hp/def (% + flat), cr (cap ที่ 100%), cd, dmgBonus, amp, sp, defShred, respen ของฝั่งโจมตี
computeTargetStats(target, damage)function (internal)
คำนวณ DEF ศัตรูจาก level (8×lvl+792) ลดด้วย DefRed debuff, รวม dmgBonus/dmgRed/amp/resred/elemRed ฝั่งเป้า
applyDamageFormula(damage, attackerStats, targetStats)function (internal)
base (atk·m.atk + hp·m.hp + def·m.def + const) × dmgBonus × crit × amp × sp × defMulti(cap 200%) × resMulti(piecewise) × elemRedMulti × reductionMulti
calculateDamage(damage, triggerBus)function (public API)
loop ทุก target → คำนวณ+log ผลลัพธ์ แล้วเรียก increaseEnergy (ถ้ามี energyGain), บวก concentoEnergy ตรง, และบวกค่าเข้า attacker.gauges

Simulator/

app/Simulator/CombatTimeline.ts
CombatTimeline.ts Core
หัวใจของระบบ — ถือ IndexedPriorityQueue ของ event ทั้งหมด, currentFrame, lock state (isGlobalLocked), และ TriggerBus กลาง 1 instance ต่อ 1 battle
class CombatTimelineclass
fields: currentFrame (default 0), onFieldChar, isGlobalLocked, triggerBus
schedule(event)push CombatEvent เข้า IPQ (key = event.name)
tick()pop event ที่ frame น้อยสุด → currentFrame=event.time → execute() → จัดการ lock ตามชนิด event (isManual→lock ON, EndAction→lock OFF+setFree, ChangeToAuto→lock OFF)
runAll()tick() วนจน IPQ ว่าง
peek() / isEmpty / sizeinspect IPQ โดยไม่ mutate

Fluent builder สร้าง Queue<RotationAction> — ใช้ตอน setup rotation ของตัวละครแต่ละตัว
class RotationBuilderclass

app/Simulator/RotationDirector.ts
RotationDirector.ts Core
ตัวกลางหลักที่ดึง RotationAction มา execute ทีละตัวแล้วขับ CombatTimeline — setupQueue ใช้ครั้งเดียวก่อน แล้วค่อยวน loopQueue จนครบ maxLoops
class RotationDirectorclass
fields: setupQueue, loopQueue, timeline, maxLoops, loopStepCount (private), currentLoopCount (public)
run()while(step()){} แล้ว timeline.runAll() drain event ที่เหลือ
step()private — เช็ค lock → nextAction() → execute() → do-while tick() จนกว่า lock จะปลดหรือ IPQ ว่าง
nextAction()private — drain setupQueue ก่อน แล้ว rotate() loopQueue จนกว่า currentLoopCount ครบ maxLoops
app/Simulator/TriggerBus.ts
TriggerBus.ts Core
pub/sub กลางของ battle — ตัวละครลงทะเบียน callback ต่อ TriggerEvent แล้ว engine emit ตอน action จริง trigger เพื่อเลี่ยงการ hardcode passive logic ตรงจุดเกิด event (ปรับจาก trigger-list ของ StarRailSimulator)
interface EnergyIncreaseContextinterface
{ unit, amount, actionType? } — payload ของ event EnergyIncrease
interface TriggerEventMapinterface
map แต่ละ TriggerEvent → payload type ของมัน — เพิ่ม event ใหม่ต้องเพิ่ม entry ที่นี่คู่กับ enum ใน Enum.ts
class TriggerBusclass
on(event, callback, priority=0)ลงทะเบียน listener — priority มากไปน้อยออกก่อน, เท่ากันเรียงตามลำดับ register
emit(event, ctx)เรียก listener ทุกตัวที่ลงทะเบียนไว้กับ event นี้ ตามลำดับ priority

app/Utils/queue.ts
queue.ts Core
Generic FIFO queue backed ด้วย object-map (ไม่ใช้ array.shift() ที่เป็น O(n)) — ทุก op เป็น O(1)
class Queue<T>class
enqueue(item)เพิ่มท้าย queue
dequeue()เอาหน้าออก, reset index เมื่อ queue ว่างสนิท
rotate()dequeue แล้ว enqueue กลับทันที — ใช้วน loop rotation
peek() / get(i) / isEmpty() / clear() / toArray() / lengthhelper อ่าน/ตรวจสอบโดยไม่ mutate (ยกเว้น clear)
app/Utils/priorityQueue.ts
priorityQueue.ts Core
Generic binary min/max-heap — ลำดับควบคุมเต็มที่ด้วย comparator function ที่ส่งเข้า constructor
class PQ<T>class
push(item)O(log n) — เพิ่ม แล้ว bubbleUp
pop()O(log n) — เอา root ออก แล้ว bubbleDown
peek()O(1) — ดู root โดยไม่เอาออก
delete(predicate)O(n) หาตำแหน่ง + O(log n) fix heap — ลบตัวแรกที่ match
toSortedArray() / size / isEmpty / clearhelper เสริม
app/Utils/indexedPriorityQueue.ts
indexedPriorityQueue.ts Core
PQ + positionMap (name → index) — เพิ่ม update/delete/has ด้วยชื่อได้ใน O(log n) แทนที่จะต้อง scan หา (ใช้เป็น backing store ของ CombatTimeline)
class IndexedPriorityQueue<T>class
push(data, name)throw ถ้าชื่อซ้ำ — ต่างจาก PQ ธรรมดา
pop() / peek()เหมือน PQ แต่ sync positionMap ไปด้วย
update(name, newData)แก้ data ของ node ที่มีอยู่ แล้ว re-bubble ตามทิศที่จำเป็น (skip ถ้า priority ไม่เปลี่ยน)
delete(name)ลบ node ตามชื่อจากตำแหน่งไหนก็ได้ในฮีป
getByName(name) / has(name) / size / isEmptyquery helper
